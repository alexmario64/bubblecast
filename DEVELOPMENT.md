# Developing Bubblecast

Canonical repository: https://github.com/alexmario64/bubblecast. All development uses a Git-connected clone of it; exported ZIPs and older workspace copies are not development sources. Read AGENTS.md for the project rules.

## Setup

### Windows (streaming PC)

1. Install Git and Node.js 22 or newer. Sign in to GitHub with the account that owns this private repository.
2. Clone the repository, then run `npm install --global pnpm@11.25.0` and `pnpm install --frozen-lockfile --ignore-scripts`.
3. Run `pnpm test` to check the checkout.
4. Run `pnpm install:background` (or double-click Install Background App.cmd). It downloads the official Electron runtime and verifies its checksum.
5. Run Start Bubblecast Background.vbs, open http://127.0.0.1:3927 and enter your channels. Sign in to platforms when you need to send chat or run polls. YouTube and Kick use your own free apps; follow [docs/own-apps.md](docs/own-apps.md) once.
6. Install Komika Axis for this Windows account if you use it as the overlay font (it is not bundled).
7. In OBS, add http://127.0.0.1:3927/dock as a Custom Browser Dock, and /overlay and /poll-overlay as Browser sources at your canvas size (3840 × 2160 for 4K). Studio → OBS setup lists every URL.
8. For automatic startup with OBS, add Bubblecast OBS.lua in OBS Tools → Scripts and point it at this checkout's Start Bubblecast Background.vbs.

Browser sign-ins, recent chat, the helper runtime and personal settings live in `.local/`, `settings.json` and `sources.json`. They are never synchronized through Git and must not be copied between machines.

### macOS (development only)

Streaming and OBS stay on Windows. On a Mac: install Node.js 22+ and pnpm as above, then `pnpm test`, `pnpm start` (server) and optionally `pnpm install:background` + `pnpm start:background` (helper; quit it from the menu bar icon). Komika Axis is found in `~/Library/Fonts` or `/Library/Fonts`. The `.cmd`, `.vbs` and OBS Lua launchers are Windows-only.

## Windows installer

`pnpm dist:win` builds `dist/Bubblecast-Setup-<version>.exe` with electron-builder (on Windows; the build config is the `build` key in package.json). The installer is per user and needs no administrator rights or Node.js: the helper runs the server inside itself. An installed copy keeps its data in `%APPDATA%\Bubblecast\.local`, `settings.json` and `sources.json` (the helper sets `BUBBLECAST_DATA`); a checkout keeps using the repository folder. On its first launch it starts with Windows, adds the dock to OBS through `obs-dock.mjs` (only while OBS is closed, since OBS rewrites its config on exit) and opens Studio.

The Windows installer workflow builds the `.exe` on every pull request; download it from the run's artifacts to test. To release, merge the version bump, then tag main with `v<version>` (for example `git tag v1.25.0 && git push origin v1.25.0`). The workflow checks the tag matches package.json and attaches the installer to that GitHub release, as `Bubblecast-Setup-<version>.exe` and as `Bubblecast-Setup.exe`, which the README's download link points to through `releases/latest/download`. The installer is unsigned, so SmartScreen warns on first run.

The installed app updates itself: the server (`updates.mjs`) asks the GitHub releases API for the latest version every 6 hours and when Studio's Check for updates is pressed. Studio shows a banner when one is newer. Install update asks the background app (`desktop/updater.mjs`) to download `Bubblecast-Setup-<version>.exe` from this repository's release, verify it against the release's `.sha256` file (published by the installer workflow), run it silently with `/S --force-run` and quit; the installer reopens Bubblecast. A checkout only reports new versions (update it with git).
## Text to speech

`tts.mjs` voices chat with the computer's own speech engine: Windows speech through PowerShell (`System.Speech`), or `say` on macOS. Chat text goes to the engine through a temporary file and environment variables, never a command line. The server's `emit()` passes each new message to `Speech.consider()`, which applies the Studio settings (`tts*` in `core.mjs`): platforms, the `!tts` command or every message, who may use it (each platform's roles, from `viewerRoles()`; the broadcaster always), a Twitch channel point reward by name, events, length and a per-viewer wait. Audio is served at `/api/tts/audio/<id>` for five minutes and played one at a time by the `/tts` browser source (`public/tts.js`), which OBS captures with "Control audio via OBS". Kick channel point redemptions are not available (Kick delivers them only by webhook). A shared wait (`ttsGlobalCooldown`) blocks commands from every platform after any message (paid rewards are still read), and `/tts` shows a countdown. The Twitch reward is linked by `ttsRewardId`: Studio can create it (needs `channel:manage:redemptions`; Twitch only lets an app change rewards it created), Studio edits to its name, cost and cooldown are sent to Twitch, `channel.channel_points_custom_reward.update` brings Twitch edits back, and a command elsewhere pauses the reward for the wait.

## Website

`site/` is the public landing page (plain HTML, no build step), published to GitHub Pages by the Website workflow when `site/` changes on main. Its download buttons point to `releases/latest/download/Bubblecast-Setup.exe`, so a new release needs no site change. The images in `site/img` come from `pnpm screenshots` (overlay showcase and dock preview, which use made-up names) cropped with `cwebp`; never publish screenshots showing real channels or chat. Spanish text lives in the page's own script.

## Workflow

1. `git checkout main && git pull --ff-only`, then create a branch (`feature/…` or `fix/…`).
2. Make changes, run `pnpm test`, and for UI changes `pnpm screenshots` (below).
3. Push the branch and open a pull request into `main`. Nothing is committed or pushed directly to `main`, and commits and PRs carry no AI attribution.
4. Merge after the Windows test check (GitHub Actions) passes.
5. On the streaming PC: `git pull --ff-only`, restart the background helper if `desktop/` changed, and refresh affected OBS sources.

### Visual checks

Run `pnpm exec playwright install chromium` once per machine before `pnpm test` or screenshots. The suite includes real Chromium overlay/server-restart regressions against isolated loopback servers; Windows CI installs Chromium before testing. `pnpm screenshots` then captures every Studio page in all four themes and at phone width, the dock states and every overlay state into `.local/screenshots/` (ignored by Git). Pass name filters to capture a subset (`pnpm screenshots polls dock`). The run fails if a page throws or a request errors. For isolated Studio checks while a signed-in helper is running, use `pnpm screenshots --offline studio-overview studio-diagnostics studio-youtube-no-app`: synthetic API data and checkout assets are served through Playwright routes; it contacts no server or live platform. It reuses the server on port 3927 or starts one, and themes are applied in the page only, so no settings are written.

Never point automated browsers or scripts at live platform sites (Twitch, YouTube, Kick, TikTok, Google). Repeated scripted traffic from one IP triggers their bot protection. Research live behavior through the helper's real windows at a normal pace.

## Architecture

- `diagnostics.mjs`: privacy-limited status snapshots and a rotating `.local/diagnostics.log` in the data folder (1 MiB plus one backup). Studio → Overview shows platform capture/session states, OBS/Aitum detection and YouTube discovery outcomes. Diagnostics observes existing state without contacting platforms.
- `server.mjs`: local HTTP/SSE server on 127.0.0.1:3927: settings, sources, relay, poll jobs and the authenticated helper command queue. Static files are served from an explicit allowlist.
- `core.mjs`: settings validation and defaults, message normalization, bots, stream event model, viewer colors and theme helpers. Shared by the server and the pages.
- `relay.mjs`, `dock-history.mjs`, `outbox.mjs`: message relay and dedupe, recent dock history, outgoing chat jobs.
- `polls.mjs`, `poll-jobs.mjs`: normalized poll state and idempotent poll create/end jobs.
- `twitch-official.mjs`: the official Twitch connection, run by the server. Device Code sign-in with the public client ID (no secret; token in `.local/twitch-auth.json`, validated hourly); EventSub WebSocket (channel owner only) for text-free redemptions and poll updates; Helix for badges, reward details, sending chat, polls and viewer counts. `twitch-live.mjs`: Twitch's official chat (IRC) connection, always used for chat, subs, raids and moderation because it is the only source that carries GIFs; when signed in it is enriched with Helix badges and reward titles. The helper never touches Twitch.
- `youtube-official.mjs`: the official YouTube connection on the streamer's own Google app (`.local/app-keys.json`, OAuth/PKCE and loopback callback, tokens in `.local/youtube-auth.json`). `youtube-discovery.mjs` runs one bounded discovery series per OBS main or Aitum output-start edge: +20, +60, +120 and +240 seconds, ending when the expected live/receiving slots fill. Repeated OBS status/recording reports never start new discovery. Studio's Find live streams and a YouTube dock-send action request one check. `findLive()` is single-flight and never reschedules itself. It uses `liveBroadcasts.list` and one batched `liveStreams.list` (`id,status,cdn`) for the active/upcoming bound stream IDs. Ingestion-name digests are compared locally against OBS main and enabled portrait Aitum outputs, reserving known formats before unknown placeholders. Automatic matches and manual choices survive restart per key digest in `.local/youtube-streams.json`; raw keys never enter status/logs, saved matches or outgoing API requests. Scheduled/ready candidates remain visible, but cannot stop the bounded checks unless live or receiving. Formats and hidden broadcasts stay in `.local/youtube-streams.json`.
  - Chat uses `liveChat/messages/stream` (resumed by page token; startup history suppressed). While OBS/Aitum is live, and for two minutes after stopping, `videos.list` refreshes known chats/viewers about every 90–110 s. Opening OBS or recording offline spends no quota. Sending and polls remain single official API actions. Adding Shorts preserves an unchanged main API reader.
  - Page fallback is allowed only without a configured Google app or after quota exhaustion. A configured app awaiting sign-in stays on the API path. `desktop/youtube-page.mjs` reads the channel's Streams tab and watch metadata in disposable signed-out windows with deadlines; the channel URL is never a chat capture window. A live-listed stream with incomplete watch metadata is retained, and existing chats are kept until their watch pages confirm they ended. Probe results are bound to their request, channel and expiry; stale results cannot replace chats. Quota exhaustion carries known video slots into page reading without navigating existing windows. Native page chat flows through the same relay/dedupe with original IDs and animated media; no Google sign-in is used for page reading. API chat pages otherwise enrich only emoji/badge artwork.
- `kick-official.mjs`: the official Kick connection, run by the server, on the streamer's own Kick app. OAuth 2.1 at id.kick.com with PKCE and the app secret. Connect Kick queues a helper window that signs into the Kick page and then opens official authorization in the same persistent partition, with a state-bound loopback callback; there is one connection entry point for API access and native polls. The loopback redirect is `http://localhost:3927/oauth/kick/callback`, scopes `user:read channel:read chat:write` (token in `.local/kick-auth.json`). `GET /public/v1/channels?slug=` about every 90–110 s finds the broadcaster ID, live state and viewer count; `POST /public/v1/chat` sends as the user, once, and an unanswered send is reported unknown, never retried. Kick only delivers chat and events by webhook, which needs a public server, so chat and events stay with the helper's anonymous Kick socket, and polls (no API) stay in the signed-in Kick page.
- `app-keys.mjs`: the streamer's own Google and Kick client IDs and secrets in `.local/app-keys.json` (mode 600). `/api/apps` returns client IDs and whether a secret is saved, never the secret. Changing an app's client ID signs that platform out.
- `youtube-merge.mjs`: while the API reads YouTube chat, the helper's signed-out page only adds what the API lacks: member badge images, Super Sticker images and member-only emojis. Its copy of a message (matched by author and letters/digits of the text) upgrades the API message in place and never adds a row, a poll or a deletion; during API startup or sign-in errors it cannot add rows. With no app or exhausted quota, native page chat goes directly through the relay instead of this enrichment merge. Standard emoji characters become YouTube's Noto images (`fonts.gstatic.com/s/e/notoemoji/15.1/<code points>/72.png`); `scripts/import-youtube-emojis.mjs` imports custom emojis from a saved live_chat page. Emoji images (`.local/youtube-emojis.json`) and each chatter's badges are remembered so they show instantly next time.
- `obs.mjs` / `youtube-slot-matching.mjs`: status-only OBS polling never reads keys. Bounded API discovery explicitly reads the main key via local `GetStreamServiceSettings` and enabled portrait Aitum keys from `plugin_config/vertical-canvas/config.json` only while its vendor is detected. Only SHA-256 digests leave that inspection. Without the Google app or quota, existing page probes supply aspect ratio/start time; known slots and independent output start order break ties without extra platform probes.
- `network-chat.mjs`: YouTube and TikTok network parsing.
- `desktop/`: the Electron helper. `main.cjs` keeps a window per platform except Twitch (YouTube's is signed out, in a non-persistent partition, and never signs in, sends or runs polls); `network-capture.mjs` reads each page's traffic; `chat-composer.mjs` sends on Kick and TikTok, and `native-poll.mjs`, `end-poll.mjs` and `shared-poll.mjs` run Kick polls; `viewer-probe.mjs` reads live viewer counts; `stream-events.mjs` parses event-socket frames.
- `desktop/tiktok-startup.mjs`: bounded session metadata checks independent of the renderer, one off-screen inactive activation per TikTok source window, and native-baseline signaling. Manage cancels activation cleanup; sign-in closure never reloads TikTok. Studio/log diagnostics expose startup and missing-session state without retaining cookie values.
- `public/event-stream.js`: shared chat/TTS/poll overlay recovery over loopback SSE, observable 15-second server heartbeats, a 45-second watchdog, bounded reconnect backoff and a reachable-server/cooldown guard before reload. Reconnection refreshes settings and preserves mounted content; it never controls platform windows or queues platform actions.
- `public/`: Studio (`index.html`, `app.js`, `style.css`), the dock (`dock.*`, `dock-layout.mjs`, `poll-board.mjs`, `poll-compose.mjs`), overlays (`overlay.*`, `poll-overlay*`), and `theme.css` with the shared theme tokens.
- `extension/`: the older Chrome-extension capture bridge, kept as an alternative to the helper.
- `test/`: unit tests; `test/browser/`: DOM fixtures with happy-dom. Fixtures do not prove live platform compatibility. `pnpm test:relay` is a live local integration check that may display synthetic overlay messages.

## Behavior reference

**Tooltips**: `public/tooltip.js` (loaded by Studio and the dock) turns any `title` into a themed tooltip after a short hover or on keyboard focus (style in `theme.css`). It lends the title to the tooltip while showing, so the system tooltip stays away, and puts it back afterwards, so keep using plain `title` attributes.

**Language**: Studio and the dock are written in English; `public/i18n.js` translates them to Spanish when `language` is `es` (Studio → Appearance, or the dock's Connections sheet; one shared setting). It swaps visible text, placeholders, tooltips and accessible labels by exact match, by pattern for built-up text ("Connected as …"), and piece by piece for text joined with " · ", and keeps watching for text the pages add later. Chat rows, names, poll questions, URLs and platform error details are left as written. New UI text needs a Spanish entry; `test/browser/i18n.test.mjs` fails on any untranslated visible text in `index.html` or `dock.html`.

**Studio** (`/`): sidebar pages addressed by hash (`/#polls`): Overview (setup checklist, live viewers, channels, quick actions), Connections, Appearance, Chat overlay, Poll overlay, Chat dock and OBS setup. Appearance and overlay changes preview instantly and save automatically; connections save explicitly because saving reloads sources. Confirmations are brief toasts; failures stay until dismissed, and a banner appears only while the background app is offline.

**Themes and brand**: interface themes are rose, red, midnight and white. All colors, including status colors, come from `public/theme.css`, shared by Studio and the dock. `uiTheme` is the app theme; `dockTheme` is `app` (match) or its own theme. The logo is the bubble trio (`public/logo-glyph.svg`) on a theme tile (`--logo-tile`); `public/favicon.svg` and `logos/tray*.png`, `logos/icon-256.png` are the full icon for tabs and the helper.

**Overlay font**: `fontFamily` accepts any installed font (Komika Axis by default) and is validated so it cannot inject CSS.

**Bots**: built-in bots (`knownBots`) plus the user's own (`ignoredBots`). Stream overlays hide bots unless listed in `overlayShownBots` (`filterBots` off shows all). The dock shows bots unless listed in `dockHiddenBots`. The relay always keeps bot messages. Follow alerts come from the streamer's own bots, not native capture.

**Stream events**: chat messages with an `event` field (`eventKinds`). Overlays show the kinds in `eventsShown` (all but follows by default); the relay and dock keep every event. Sources: Twitch chat (IRC) `USERNOTICE` for subs, resubs, gifted subs, gift bombs (individual gifts collapsed), raids and watch streaks; redemptions with text via IRC `custom-reward-id`, and text-free redemptions via EventSub when signed in as the channel owner (reward titles and colors from Helix; without signing in, redemptions show without a title); Kick `KicksGifted`; YouTube Super Chats, stickers, memberships and gift memberships. Kick subs and redemptions and TikTok events are not captured yet.

**Live viewers**: Twitch comes from Helix Get Streams when signed in, YouTube from `videos.list` when connected. For Kick and TikTok the helper runs `viewer-probe.mjs` inside each open platform page, about every 90–110 s, and reports `{live, viewers}`: Kick `livestream.viewer_count`, TikTok `liveRoomStats.userCount` (live counts unverified). These are undocumented read-only endpoints and can change.

**Polls**: the poll pane opens beside any chat view (stacked on narrow docks) without replacing chat iframe sessions. Combined totals sum known answer counts; percentage-only sources are labeled separately. YouTube Live and Shorts are separate destinations. Final results stay in the dock for five minutes and on the stream overlay for `pollResultSeconds` (15 s by default). Twitch and YouTube polls run and end through their APIs; Kick polls run in the signed-in Kick page. Poll overlay styling uses the `poll*` settings in `core.mjs`.

**Platform access**: there is no hosted server. Anything done as the streamer's account uses official APIs only. Twitch and YouTube are official, and Kick sends chat and reads viewers through its official API on each streamer's own app. Platforms without an official API are read anonymously, read-only and at a natural pace, and are never automated.
